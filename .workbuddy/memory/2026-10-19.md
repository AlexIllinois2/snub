# 2026-10-19

## 修复 HailApp 启动崩溃（ForegroundServiceStartNotAllowedException）

- 崩溃日志：`snub-crash-20261019-143041.log.txt`（Redmi Note 8 Pro / Android 16 / SDK 36，凌晨后台时段）
- 根因：`HailApp.onCreate()` 在进程被后台创建时无条件 `startForegroundService(SwipeFreezeService)`，Android 12+ 后台 FGS 启动限制抛 `ForegroundServiceStartNotAllowedException`，在 Application.onCreate 中未捕获 → `Unable to create application` 必崩。触发路径：root watchdog 的 `am start-foreground-service`、START_STICKY 重启、ROM 自动重启等。
- 修复：
  - `HailApp` 新增 `startForegroundServiceSafely()`：try/catch 包住启动，被拒绝时记入 `pendingFgsStarts` 挂起；`registerActivityLifecycleCallbacks` 监听 `onActivityStarted`，应用进前台时重试。
  - `setSwipeFreezeService` / `setLowBatteryShutdownService` / `setAutoFreezeService` 全部改走安全通道；停服务时调用 `cancelPendingFgsStart()` 同步取消挂起项，防止"关闭后又在前台被重拉起来"。
  - `BootReceiver` 也改用安全通道（个别 ROM 连 BOOT_COMPLETED 豁免也拒）。
  - `setAutoFreezeService(context: Context = app)` 的无用 context 形参已移除（所有调用方本就无参）。
  - `HLog` 新增 `w()` 便捷方法。
- 验证：`:app:compileReleaseKotlin` 通过。
- 附带发现：工作区 HailApp.kt 有一个未提交的笔误 `AppCompatDelegate.MODE_FOLLOW_SYSTEM`（git 提交里是 `MODE_NIGHT_FOLLOW_SYSTEM`），导致 HEAD 实际无法编译；已改为 appcompat 1.6+ 推荐的非废弃常量 `MODE_NIGHT_UNSPECIFIED`（语义=跟随系统）。
- 构建：`:app:assembleRelease` 成功（4m37s），产物 `app/build/outputs/apk/release/Snub-v1.11.0-g7ceda6b.apk`（5.5MB，versionCode 35，回退 debug 签名）。
- 同类隐患：服务自身在 onCreate/onStartCommand 里调 `startForeground()` 只有经 `startForegroundService` 成功路径才会到达，暂不需改。
