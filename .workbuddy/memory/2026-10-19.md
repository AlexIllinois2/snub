## 修复 HailApp 启动崩溃（ForegroundServiceStartNotAllowedException）

- 崩溃日志：`snub-crash-20261019-143041.log.txt`（Redmi Note 8 Pro / Android 16 / SDK 36，凌晨后台时段）
- 根因：`HailApp.onCreate()` 在进程被后台创建时无条件 `startForegroundService(SwipeFreezeService)`，Android 12+ 后台 FGS 启动限制抛 `ForegroundServiceStartNotAllowedException`，在 Application.onCreate 中未捕获 → `Unable to create application` 必崩。触发路径：root watchdog 的 `am start-foreground-service`、START_STICKY 重启、ROM 自动重启等。
- 修复：
  - `HailApp` 新增 `startForegroundServiceSafely()`：try/catch 包住启动，被拒绝时记入 `pendingFgsStarts` 挂起；`registerActivityLifecycleCallbacks` 监听 `onActivityStarted`，应用进前台时重试。
  - `setSwipeFreezeService` / `setLowBatteryShutdownService` / `setAutoFreezeService` 全部改走安全通道；停服务时调用 `cancelPendingFgsStart()` 同步取消挂起项，防止"关闭后又在前台被重拉起来"。
  - `BootReceiver` 也改用安全通道（个别 ROM 连 BOOT_COMPLETED 豁免也拒）。
  - `setAutoFreezeService(context: Context = app)` 的无用 context 形参已移除（所有调用方本就无参）。
  - `HLog` 新增 `w()` 便捷方法。
- 验证：`:app:compileReleaseKotlin` 通过。
- 附带发现：工作区 HailApp.kt 有一个未提交的笔误 `AppCompatDelegate.MODE_FOLLOW_SYSTEM`（git 提交里是 `MODE_NIGHT_FOLLOW_SYSTEM`），导致 HEAD 实际无法编译；已改为 appcompat 1.6+ 推荐的非废弃常量 `MODE_NIGHT_UNSPECIFIED`（语义=跟随系统）。
- 构建：`:app:assembleRelease` 成功（4m37s），产物 `app/build/outputs/apk/release/Snub-v1.11.0-g7ceda6b.apk`（5.5MB，versionCode 35，回退 debug 签名）。
- 同类隐患：服务自身在 onCreate/onStartCommand 里调 `startForeground()` 只有经 `startForegroundService` 成功路径才会到达，暂不需改。

## 修复 PagerFragment 延迟 Runnable NPE（snub-crash-20261019-171921.log.txt）

- 崩溃日志：`snub-crash-20261019-171921.log.txt`（Redmi Note 8 Pro / Android 16 / SDK 36，1.11.0-g7ceda6b (35)）
- 反混淆：用 `app/build/outputs/mapping/release/mapping.txt`（pg_map_id 与日志 r8-map-id 一致）。`km1`=PagerFragment，`e0`=getTabs(:75)，`f0`=getTag(:77)，`b0`=getFrozenTab(:78)；`v7` 是 R8 水平合并类（含 Compose 的 AndroidContentCaptureManager lambda），其 `run` 内联帧 `102:107` 指向 `PagerFragment$onCreateView$2$1.onScrollStateChanged$lambda$0$0`（PagerFragment.kt:102）。
- 还原栈：延迟 Runnable（:102 `postDelayed({ if (!frozenTab) show() }, 1000)`，post 在 Activity 级 FAB 上，生命周期长于 Fragment 视图）→ frozenTab → tag → tabs → `(parentFragment as? HomeFragment)?.binding?.tabs` → `HomeFragment.binding` 的 `_binding!!`（HomeFragment.kt:21）空断言崩溃。dexdump 证实 `!!` 被编译为 `invoke-virtual Object.getClass()` 空检查（`km1.e0:000f`），NPE 消息 "Attempt to invoke virtual method getClass()" 即 Kotlin `!!` 的典型形态。`?.binding` 只能挡 getter 返回值，挡不住 getter 内部 `!!` 抛出——第 523 行注释"视图已销毁则返回"的本意被 `!!` 破坏。
- 触发场景：滚动列表停止后 1 秒内切换底部导航/ViewPager2 页面，HomeFragment.onDestroyView 置 `_binding=null`，Runnable 到时执行即崩。
- 修复：
  - `HomeFragment` 新增 `bindingOrNull`（可空访问器）。
  - `PagerFragment.tabs/adapter` 改走 `bindingOrNull`（`adapter` 同隐患一并修）。
  - 延迟 Runnable 加 `_binding != null` 守卫（与本文件既有惯用法一致），避免销毁后还把 Activity FAB 弹回来。
- 验证：`:app:assembleRelease` 通过（5m44s），产物 `Snub-v1.11.0-g3185fc1.apk`；dexdump 新包 `km1.e0`：`getClass()` 陷阱已消失，变为 `if-eqz` 空检查后 return null（000f 处）。
